# 2026-07-14 (화) — 핵심 가설을 더 작고 선명하게 만들기

## Q. 해결하고 싶은 불편 1개

주차 기록을 입력하는 과정 자체도 불편하지만, 주차가 끝난
시점에 주차 기록을 위해 서비스에 접근하는 과정 또한 번거롭고,
까먹을 가능성이 높다.

## Q. 가설/가정 (한 문장)

사용자가 운전을 끝낸 시점에 자동으로 주차 위치를 기록할 것인지
물어보는 알림 기능을 구현하면 접근성을 더 높일 수 있을 것이다.

## 한 일

- 가상 센서 조작판으로 운전 시작 → 블루투스 연결 → 주행 종료(걷기
  전환)를 시뮬레이션하는 UI 구현
- 차량 블루투스 연결 해제 + 걷기 상태 전환 시, 또는 블루투스 등록
  없이 운전→걷기로 전환될 때 자동으로 "지금 기록하기" 푸시 알림이
  뜨도록 구현
- 설정 화면에 자동 감지 on/off, 차량 블루투스 기기 등록 기능 추가

## 한 일 (오후 — 배포/수집 인프라)

가설 검증 자체는 오전에 끝났고, 오후에는 실제로 사용자에게
보여주고 의견을 받을 수 있는 통로를 만드는 데 집중했다.

- Gemini Canvas `index.html` 프로토타입을 Next.js(App Router,
  TS, Tailwind)로 포팅하고 Vercel에 배포 (개인 계정 저장소)
- 메인 페이지 하나였던 구조를 랜딩페이지(`/`) · 체험
  시뮬레이션(`/simulate`) · 체험후기(`/feedback`) 3단으로 개편
- 랜딩페이지를 "문제 제기 → 해결 → 사용 흐름 → 투명성" 순서로
  재구성 (기존 기능 나열형 구성에서 변경)
- 기존에 쓰던 습관 조사용 구글폼을 "체험후기" 전용으로 재구성
  제안 (사전 습관 조사 섹션 제거, 자동 감지 알림 관련 문항 추가
  제안) — 실제 문항 수정은 사용자가 구글폼에서 직접 진행 예정
- `/feedback`에 해당 구글폼을 임베드해 사이트 디자인은 유지하면서
  응답은 기존 구글폼/시트에 쌓이도록 연결
- 체험 완료 직후 뜨는 평가 유도 팝업이 화면을 가리는 문제를
  발견해 크기 축소 + 1.8초 지연 노출로 수정, 팝업을 놓쳐도
  접근 가능하도록 상단 네비게이션에 "설문 참여" 탭 상시 노출

## 상태

- 자동 감지 알림 기능은 프로토타입 상에서 구현 완료.
- 체험 → 피드백 수집까지 이어지는 전체 흐름(배포, 설문 연결)도
  오늘 구축 완료.
- **아직 실사용자 피드백은 받지 못함.** 구글폼 문항 업데이트는
  사용자가 내일 진행 예정.

## 다음에 확인할 것

  문제를 줄여주는지, 오히려 불필요한 알림으로 느껴지진 않는지
  물어본다.
- (내일) 실제로 받은 피드백을 바탕으로 프로토타입을 업데이트한다.
