# 프로젝트 메모리

## 프로젝트 개요

"마지막 주차" — 주차 위치를 기록하고 빠르게 다시 찾을 수 있게
돕는 앱 프로토타입. 최종적으로는 네이티브 앱을 목표로 하지만,
현재 단계는 **프로토타이핑**이다. 지금은 실제 앱처럼 보이는
웹 화면에서, 앱을 쓰는 것처럼 시뮬레이션할 수 있는 웹사이트를
만들어 빠르게 검증하는 데 집중한다.

- 프로토타입: Gemini Canvas로 만든 `index.html` (참고용 초안)
- Next.js(App Router, TS, Tailwind)로 재구성 완료, Vercel에 배포되어 있음
- 저장소: 개인 계정(`origin`)에 우선 push, 추후 organization으로 이전 가능성 있음

## 사이트 구조 (2026-07-14 개편)

앱 체험 시뮬레이션 단일 페이지였던 구조를, 실제 서비스처럼 방문자를
맞이하고 체험 후 피드백까지 자연스럽게 이어지도록 개편했다. 이건
사용자 피드백이 아니라 자체 기획 결정이라 날짜별 로그에는 남기지
않고 여기에만 기록한다.

- `/` — 제품 랜딩페이지. 문제 제기 → 해결 → 사용 흐름 → 투명성
  섹션 순서로 구성, "체험해보기" CTA. 문제 3가지는 실제 로그에
  있던 불편을 그대로 가져와 해결 기능과 1:1로 짝지어 배치했다
- `/simulate` — 기존에 메인이었던 스마트폰 시뮬레이션 프로토타입
  (`ParkingApp`). 상단 탭("홈" / "앱 체험해보기" / "설문 참여")으로
  다른 페이지와 오간다
- `/feedback` — 체험 후기 설문 페이지. 기존에 쓰던 구글폼(사전
  습관 조사용)을 "체험후기" 전용으로 재구성해 iframe으로 임베드.
  응답은 그대로 구글폼/연동 시트에 쌓인다. 폼 문항 자체는 코드가
  아니라 구글폼에서 직접 수정 (수정하면 코드 변경 없이 반영됨)
- 시뮬레이션에서 주차 위치 저장(성공 화면 도달)을 완료하면 1.8초
  뒤 우측 하단에 작은 평가 유도 팝업이 뜨고, "평가 남기기"를
  누르면 `/feedback`으로 이동한다. 팝업을 놓치거나 닫아도 상단
  "설문 참여" 탭으로 언제든 갈 수 있다

## 매일 반복하는 사이클

1. 불편을 고른다
2. 가설을 세운다
3. 작은 프로토타입을 만든다

5. 배운 것을 정리한다
